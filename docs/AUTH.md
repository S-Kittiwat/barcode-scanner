# ระบบยืนยันตัวตน — วิธีติดตั้งและดูแล

สำหรับทีมไม่เกิน 30 คน เครื่องใครเครื่องมัน อายุเซสชัน 30 วัน

---

## ปัจจุบันเทียบกับหลังติดตั้ง

| | ตอนนี้ | หลังติดตั้ง |
|---|---|---|
| ใครก็เข้าได้ถ้ามีลิงก์ | ใช่ | ไม่ ต้องมีบัญชีที่ผู้ดูแลสร้าง |
| ยิง API ตรงโดยไม่ผ่านหน้าเว็บ | ทำได้ | ไม่ได้ ต้องมี token |
| สวมชื่อคนอื่นตอนบันทึก | ทำได้ | ไม่ได้ เซิร์ฟเวอร์เขียนตัวตนจริงทับ |
| ถอนสิทธิ์คนที่ลาออก | ทำไม่ได้ | ลบได้ทันที |
| รู้ว่าใครล็อกอินเมื่อไหร่ | ไม่รู้ | มีชีต `LoginLog` |

**จุดที่สำคัญที่สุด** — `withAuth_` ใน `doPost` เขียน `emp_id`, `emp_name`, `site` จากข้อมูลฝั่งเซิร์ฟเวอร์ทับสิ่งที่หน้าเว็บส่งมาเสมอ
แปลว่า audit trail ในชีต `Items` เชื่อถือได้จริง ซึ่งเป็นเงื่อนไขจำเป็นถ้าจะใช้สถิติความแม่นที่เก็บไว้ตัดสินใจอะไร

## ติดตั้งครั้งแรก (ราว 20 นาที)

### 1. ตั้ง AUTH_PEPPER

รันฟังก์ชัน `generateAuthPepper()` หนึ่งครั้งจากหน้า Apps Script
ระบบจะสร้างและเก็บค่าให้เอง ไม่ต้องคัดลอกอะไร

รายละเอียดและวิธีทางเลือก ดูหัวข้อ **AUTH_PEPPER — สร้างและตั้งค่า** ท้ายเอกสาร

### 2. วางไฟล์

- `gas/Auth.gs` → สร้างไฟล์ใหม่ใน Apps Script
- `gas/Code.gs` → แทน `doPost` เดิม
- `js/auth.js` → วางในโฟลเดอร์ `js/` ของ repo

### 3. สร้างชีต

รัน `setupAuthSheets()` หนึ่งครั้งจากหน้า Apps Script — จะได้ชีต `Users`, `Sessions`, `LoginLog`

### 4. ตั้งค่าการสมัครเอง

Script Properties เพิ่มอีกสองค่า

```
ALLOWED_EMAIL_DOMAIN = brs-group.com
ADMIN_EMAIL          = อีเมลผู้ดูแล (รับแจ้งเตือนเมื่อมีคนสมัคร)
```

### ใส่หลายโดเมน

คั่นด้วย `,` หรือ `|` หรือเว้นวรรค ใช้แบบไหนก็ได้

```
ALLOWED_EMAIL_DOMAIN = brs-group.com, boonrawd.co.th, singha.com
```

**รับโดเมนย่อยด้วย** ให้ขึ้นต้นด้วยจุด

```
ALLOWED_EMAIL_DOMAIN = .brs-group.com
```
จะรับทั้ง `somchai@brs-group.com` และ `somchai@th.brs-group.com`

ผสมกันได้ เช่น `.brs-group.com, boonrawd.co.th`

**ทำไมไม่ใช้ endsWith** — ถ้าเทียบด้วยลงท้าย โดเมนพวกนี้จะหลุดเข้ามาได้ทั้งหมด
`evil-brs-group.com` · `brs-group.com.evil.com`
ระบบจึงเทียบตรงตัวเป็นค่าเริ่มต้น และรับโดเมนย่อยเฉพาะเมื่อสั่งด้วยจุดนำหน้าเท่านั้น

**แก้ที่เดียวพอ** หน้าสมัครดึงรายการนี้จากเซิร์ฟเวอร์ผ่าน `getAuthConfig`
ไม่ต้องไปแก้ใน `js/auth.js` อีก (ค่าในไฟล์นั้นเป็นแค่ค่าสำรองตอนดึงไม่สำเร็จ)

เปลี่ยนค่าแล้ว**มีผลทันที** ไม่ต้อง Deploy ใหม่ เพราะ Script Property อ่านตอนรัน

วาง `gas/Register.gs` เป็นไฟล์ใหม่ แล้วรัน `setupRegisterSheets()` หนึ่งครั้ง

> เพิ่มผู้ใช้เองได้ด้วย `addUser()` แต่ต้องใช้ค่า hash จาก `admin-tool.html`
> ใส่รหัสผ่านดิบไม่ได้ — ดูหัวข้อ **สร้างบัญชีผู้ดูแลคนแรก**

role ที่ใช้ได้: `warehouse` · `delivery` · `admin`

### 5. ตั้ง trigger ล้างของเก่า

Triggers → Add Trigger → รายวัน สองตัว: `cleanupExpiredSessions` และ `cleanupExpiredCodes`

### 6. Deploy เป็น New version

## แก้ `login.html`

เปลี่ยนจากฟอร์มกรอกชื่อเป็นฟอร์มล็อกอินจริง — ต้องมี **รหัสพนักงาน** กับ **รหัสผ่าน** เท่านั้น

ช่องชื่อ อีเมล ทีม และไซต์ **ต้องเอาออกทั้งหมด** เพราะข้อมูลเหล่านี้มาจากเซิร์ฟเวอร์แล้ว
ถ้ายังให้กรอกเองจะกลับไปเป็นปัญหาเดิม คือคนเลือกไซต์ที่ไม่ใช่ของตัวเองได้

```js
import { login, checkPasswordStrength, consumeReturnTo } from './js/auth.js';

async function doLogin() {
  const empId = document.getElementById('empId').value.trim();
  const pw = document.getElementById('password').value;
  try {
    const s = await login(DOCSCAN_CONFIG.API_URL, empId, pw);
    location.href = s.mustChangePassword ? 'change-password.html' : consumeReturnTo();
  } catch (e) {
    showError(e.message);   // ข้อความจากเซิร์ฟเวอร์เป็นภาษาไทยแล้ว
  }
}
```

## แก้หน้าอื่น

แทนที่ `DocScanAuth` ที่ฝังอยู่ในแต่ละไฟล์:

```js
import { requireAuth, authFetch, logout } from './js/auth.js';
const session = requireAuth();
```

แล้วเปลี่ยนทุกที่ที่เรียก `apiFetch` เป็น `authFetch` — token จะถูกแนบให้เอง

## การสมัครใช้งานเอง

### ขั้นตอนฝั่งผู้ใช้

1. กรอกฟอร์มสมัคร — รหัสพนักงาน ชื่อ อีเมลบริษัท ไซต์ ทีม และ**ตั้งรหัสผ่านเอง**
2. ระบบส่งรหัส 6 หลักไปที่อีเมล (อายุ 15 นาที)
3. กรอกรหัสยืนยัน → เข้าคิวรอผู้ดูแลอนุมัติ
4. เมื่ออนุมัติแล้ว ระบบส่งอีเมลแจ้ง เข้าใช้งานได้ด้วยรหัสที่ตั้งไว้

**ทำไมต้องยืนยันอีเมลก่อนเข้าคิว** ถ้าให้เข้าคิวได้ทันที ใครก็ยิงคำขอปลอมมาถล่มจนผู้ดูแลแยกไม่ออกว่าอันไหนจริง
เมื่อบังคับให้ยืนยันอีเมลบริษัทก่อน คิวที่ผู้ดูแลเห็นจะเป็นคนที่มีอีเมลบริษัทจริงทั้งหมด

### ขั้นตอนฝั่งผู้ดูแล

ดูรายการที่รออนุมัติ
```js
listPendingApprovals()
```

อนุมัติ
```js
approveUser('E001')                        // ตามที่ผู้ใช้ขอมา
approveUser('E001', 'delivery')            // เปลี่ยน role
approveUser('E001', 'warehouse', 'NDC-วังน้อย')   // เปลี่ยนทั้ง role และไซต์
```

ปฏิเสธ
```js
rejectUser('E001', 'ไม่พบชื่อในระบบพนักงาน')
```

**สิ่งที่ผู้ดูแลต้องตรวจก่อนอนุมัติ** — ระบบยืนยันได้แค่ว่าคนนี้มีอีเมลบริษัทจริง
แต่ยืนยันไม่ได้ว่ารหัสพนักงานที่กรอกเป็นของเขาจริง หรือควรได้สิทธิ์ไซต์นั้น
**การอนุมัติจึงเป็นจุดที่คนต้องตรวจจริง ไม่ใช่กดผ่านอัตโนมัติ** โดยเฉพาะ role และไซต์

---

## สิ่งที่ผู้ดูแลต้องทำประจำ

### เมื่อมีคนสมัครใหม่
มีอีเมลแจ้งอัตโนมัติ → ตรวจตัวตนกับรายชื่อพนักงาน → `approveUser()` หรือ `rejectUser()`

### เมื่อมีคนลืมรหัส
**ไม่ต้องทำอะไร** ผู้ใช้กดลืมรหัสผ่านแล้วตั้งใหม่เองผ่านอีเมลได้
ระบบจะตัดทุกเซสชันของคนนั้นทันทีเมื่อตั้งรหัสใหม่สำเร็จ

ทำเองได้ถ้าจำเป็น (เช่นผู้ใช้เข้าอีเมลไม่ได้) — ต้องใช้ค่า hash จาก `admin-tool.html`
```js
resetPassword('E00X', '<hash 64 ตัว>', true)
```

### เมื่อมีคนลาออก
```js
deactivateUser('E00X')
```
**ทำทันทีในวันสุดท้าย** ไม่ต้องรอ เพราะ session อายุ 30 วัน

### เมื่อเครื่องหายหรือถูกขโมย
```js
revokeAllSessions('E00X')
```

### ทุกสัปดาห์
เปิดชีต `LoginLog` ดูสามอย่าง
- ล็อกอินล้มเหลวถี่ผิดปกติ โดยเฉพาะรหัสพนักงานที่ไม่มีอยู่จริง = มีคนลองเดา
- คำขอ `reset` ถี่ผิดปกติของคนเดียว = อาจมีคนพยายามเข้าบัญชีคนอื่น
- คำขอสมัครที่ค้างในคิวนาน = ผู้ดูแลลืมอนุมัติ ทำให้คนทำงานไม่ได้

## สร้างบัญชีผู้ดูแลคนแรก

ต้องทำหลังตั้ง `AUTH_PEPPER` และรัน `setupAuthSheets()` แล้ว

**ทำไมต้องมีขั้นตอนพิเศษ** — GAS ไม่มี PBKDF2 จึงคำนวณค่า hash แบบเดียวกับเบราว์เซอร์ไม่ได้
ถ้าใส่รหัสผ่านดิบลงใน `addUser()` จะได้บัญชีที่**ล็อกอินไม่ได้เลย**
`admin-tool.html` จึงมีหน้าที่คำนวณค่านี้ให้ในเบราว์เซอร์

### ขั้นตอน

**1. เปิด `admin-tool.html` บนเว็บ**

```
https://s-kittiwat.github.io/barcode-scanner/admin-tool.html
```

ต้องเปิดผ่าน https เท่านั้น เปิดไฟล์จากเครื่องตรง ๆ จะใช้ไม่ได้เพราะ WebCrypto ต้องการ secure context

**2. กรอกสองช่อง**

- รหัสพนักงาน — เช่น `ADMIN01` **ต้องตรงกับที่จะใส่ใน addUser เป๊ะ ๆ** เพราะมีผลกับค่า hash
- รหัสผ่านที่ต้องการตั้ง

เลือก Role เป็น `admin` และ "ไม่บังคับเปลี่ยนรหัส" เพราะคุณตั้งรหัสให้ตัวเอง

**ช่องไซต์** สำหรับ admin ใส่ `ALL` ได้ — ผู้ดูแลไม่ผูกกับไซต์ใดไซต์หนึ่ง เห็นข้อมูลทุกไซต์
(ค่าว่าง `*` `ทุกไซต์` ก็ได้ผลเหมือนกัน แต่ `ALL` อ่านง่ายกว่าเวลาเปิดดูในชีต)

**บัญชีที่ไม่ใช่ admin ห้ามเว้นว่าง** ระบบจะปฏิเสธตั้งแต่ตอนสร้าง เพราะค่าว่างจะกลายเป็น
"ไม่กรอง" ซึ่งเท่ากับให้คนคลังเห็นข้อมูลของทุกไซต์

**3. กดคำนวณ แล้วกดปุ่มคัดลอกคำสั่ง**

จะได้คำสั่งหน้าตาแบบนี้

```js
addUser(
  'ADMIN01',
  'ชื่อ-นามสกุล',
  'อีเมล@brs-group.com',
  'ALL',
  'admin',
  '3f9a2c1e...64ตัว...',
  false
)
```

**4. แก้ชื่อ อีเมล และไซต์ให้ถูก** แล้วเอาไปวางใน Apps Script

- เปิด Apps Script → สร้างไฟล์ชั่วคราวหรือใช้ `Auth.gs`
- วางคำสั่งไว้ในฟังก์ชันชั่วคราว

```js
function createMyAdmin() {
  return addUser(
    'ADMIN01', 'ชื่อ-นามสกุล', 'อีเมล@brs-group.com',
    'ALL', 'admin',
    '3f9a2c1e...', false
  );
}
```

- เลือก `createMyAdmin` จากดรอปดาวน์ → กด **Run**
- ควรขึ้นว่า `เพิ่มผู้ใช้ ADMIN01 เรียบร้อย`

**5. ลบฟังก์ชันชั่วคราวทิ้ง** เพราะข้างในมีค่า hash ติดอยู่

**6. ทดสอบล็อกอินทันที** ที่ `login.html` ด้วยรหัสพนักงานและรหัสผ่านที่ใช้สร้าง hash

**ถ้าล็อกอินไม่ผ่าน หยุดตรงนี้** อย่าไปต่อ สาเหตุที่พบบ่อย

| อาการ | สาเหตุ |
|---|---|
| รหัสพนักงานหรือรหัสผ่านไม่ถูกต้อง | กรอก empId ใน admin-tool ไม่ตรงกับใน addUser |
| เหมือนกัน | คัดลอก hash ไม่ครบ หรือติดเครื่องหมายคำพูด |
| เหมือนกัน | `AUTH_PEPPER` ถูกเปลี่ยนหลังสร้างบัญชี |
| เซสชันหมดอายุ | ยังไม่ได้ Deploy version ใหม่ |

**7. ลบ `admin-tool.html` ออกจาก repo**

หน้านี้ไม่ได้เก็บความลับอะไร (คำนวณในเครื่องล้วน ๆ ไม่ส่งข้อมูลออก)
แต่ไม่มีเหตุผลให้เปิดทิ้งไว้ เพราะผู้ใช้ทั่วไปสมัครเองผ่าน `register.html` ได้

### สร้างบัญชีให้คนอื่น

ปกติ**ไม่ต้องทำ** ให้เขาสมัครเองที่ `register.html` แล้วคุณกด `approveUser()`
วิธีนั้นดีกว่าเพราะเขาตั้งรหัสเอง คุณไม่ต้องรู้รหัสผ่านของใคร

ใช้ `admin-tool.html` เฉพาะกรณีจำเป็น เช่นคนที่เข้าอีเมลบริษัทไม่ได้
กรณีนั้นให้เลือก **"บังคับ (ตั้งรหัสให้คนอื่น)"** เพื่อให้เขาเปลี่ยนรหัสตอนล็อกอินครั้งแรก
และ**ส่งรหัสชั่วคราวทางช่องทางส่วนตัว ไม่ใช่กลุ่มแชท**

## AUTH_PEPPER — สร้างและตั้งค่า

`AUTH_PEPPER` คือค่าลับที่ใช้ผสมตอนแฮชรหัสผ่าน เก็บใน Script Properties **ไม่ใช่ในชีต**
ถ้าวันหนึ่งชีตถูกแชร์ผิดคน แฮชรหัสผ่านที่หลุดไปจะเอาไปถอดไม่ได้ถ้าไม่มีค่านี้

### วิธีที่แนะนำ — ให้ Apps Script สร้างและตั้งให้เอง

ปลอดภัยที่สุด เพราะค่าถูกสร้างและเก็บในที่เดียวกัน ไม่ต้องผ่านคลิปบอร์ด
จึงไม่มีทางก๊อปไม่ครบ ติดเครื่องหมายคำพูด หรือค้างอยู่ในประวัติคลิปบอร์ด

1. เปิด Google Sheet ของระบบ → เมนู **Extensions → Apps Script**
2. เปิดไฟล์ `Auth.gs`
3. ที่แถบด้านบน เลือกฟังก์ชัน `generateAuthPepper` จากรายการดรอปดาวน์
4. กด **Run** (ครั้งแรกจะขอสิทธิ์ ให้กด Review permissions → เลือกบัญชี → Advanced → Go to ... → Allow)
5. ดูข้อความใน Execution log ควรขึ้นว่า `ตั้ง AUTH_PEPPER เรียบร้อย (ยาว 64 ตัว)`

ตรวจว่าตั้งจริงไหม: **Project Settings** (ไอคอนเฟือง) → เลื่อนลงไปที่ **Script Properties**
ต้องเห็น `AUTH_PEPPER` พร้อมค่ายาว ๆ

ถ้าขึ้นว่า *มี AUTH_PEPPER อยู่แล้ว* แปลว่าเคยตั้งไว้แล้ว **ไม่ต้องทำอะไรต่อ**

### วิธีทางเลือก — สร้างจาก Console เบราว์เซอร์

ใช้เมื่ออยากเห็นค่าเองหรืออยากเก็บสำรองไว้

1. เปิดเบราว์เซอร์ กด **F12** (Mac: `Cmd + Option + I`) แล้วไปแท็บ **Console**
2. พิมพ์บรรทัดนี้แล้วกด Enter — **พิมพ์เอง อย่าก๊อปวาง** เพราะ Chrome จะบล็อกการวางในคอนโซล
   (ถ้าจำเป็นต้องวางจริง ๆ Chrome จะให้พิมพ์คำว่า `allow pasting` ก่อน)
   ```js
   crypto.randomUUID().replaceAll('-','') + crypto.randomUUID().replaceAll('-','')
   ```
3. จะได้ผลลัพธ์หน้าตาแบบนี้ **พร้อมเครื่องหมายคำพูดครอบ**
   ```
   '3f9a2c1e8b7d4a06...'
   ```
4. คัดลอกเฉพาะข้างในเครื่องหมายคำพูด **ห้ามเอา `'` ติดไปด้วย**
   ถ้าติดไปจะไม่มีใครล็อกอินได้ และหาสาเหตุยากมาก
5. ไปที่ Apps Script → **Project Settings** → **Script Properties** → **Add script property**
   - Property: `AUTH_PEPPER`
   - Value: วางค่าที่คัดลอกมา
6. กด **Save script properties**

> ถ้าใช้ `crypto.randomUUID() + crypto.randomUUID()` แบบไม่ตัดขีด ก็ใช้ได้เหมือนกัน
> แค่จะมี `-` ปนอยู่ ซึ่งไม่มีผลอะไร

### ข้อควรระวัง

**ห้ามเปลี่ยนค่านี้หลังมีผู้ใช้แล้ว** ถ้าเปลี่ยน แฮชรหัสผ่านทั้งหมดในชีตจะใช้ไม่ได้ทันที
ทุกคนล็อกอินไม่ได้ และต้องให้ผู้ดูแลตั้งรหัสใหม่ให้ทุกคน

**ห้ามส่งค่านี้ทางแชท อีเมล หรือใส่ในโค้ด** ค่านี้ไม่ต้องจดไว้ที่ไหนเลย
ไม่มีใครต้องใช้มันอีก รวมทั้งตัวคุณเอง ระบบอ่านเองจาก Script Properties

**ถ้าสงสัยว่าหลุด** ให้รัน `regenerateAuthPepper()` แล้วตั้งรหัสใหม่ให้ทุกคนด้วย `resetPassword()`
ฟังก์ชันนี้จะตัดทุกเซสชันทิ้งอัตโนมัติ

**ความยาว** 64 ตัวอักษรเพียงพอมาก ยาวกว่านี้ไม่ได้ปลอดภัยขึ้นในทางปฏิบัติ

## ข้อจำกัดที่ต้องรู้

**token เก็บใน localStorage** เพราะ GitHub Pages กับ GAS อยู่คนละโดเมน ใช้คุกกี้ HttpOnly ไม่ได้
แปลว่าถ้ามีช่องโหว่ XSS ในหน้าเว็บ token จะถูกขโมยได้ — ต้องระวังการเอาข้อมูลจาก CSV ไปใส่ `innerHTML` โดยไม่ผ่าน `esc()`

**PBKDF2 ทำงานฝั่งเครื่องผู้ใช้เท่านั้น** GAS ไม่มี PBKDF2 ให้ใช้
`addUser()` และ `resetPassword()` จึงรับเฉพาะค่า hash ที่คำนวณจากเบราว์เซอร์ ไม่รับรหัสผ่านดิบ
ใช้ `admin-tool.html` คำนวณ — และมี `assertPwHash_()` คอยกันไม่ให้เผลอใส่รหัสดิบลงไป

**ระบบนี้เหมาะกับขนาดงานนี้ แต่ไม่ใช่ระดับที่จะเก็บข้อมูลอ่อนไหวมาก** ถ้าวันหนึ่งขอบเขตขยายไปถึงข้อมูลที่หลุดแล้วเสียหายหนัก ควรย้ายไป backend จริงแทน GAS

**โควตาอีเมลของ GAS** บัญชี Gmail ทั่วไปส่งได้ราว 100 ฉบับต่อวัน
ที่ 30 คนเพียงพอมาก แต่ถ้าโควตาเต็มขึ้นมา คนจะสมัครและตั้งรหัสใหม่ไม่ได้ทั้งวัน
ควรตรวจตัวเลขนี้จริงกับบัญชีที่ใช้ก่อนเปิดใช้งาน

**อีเมลจะถูกส่งจากบัญชี Google ของเจ้าของสคริปต์** ไม่ใช่จากที่อยู่ของบริษัท
อาจเข้าโฟลเดอร์สแปมได้ ควรแจ้งผู้ใช้ไว้ล่วงหน้าและทดสอบกับผู้ใช้จริงสักคนก่อน

**การสมัครเองเปิดช่องให้คนนอกลองยิงคำขอเข้ามา** จึงมีด่านกันไว้สี่ชั้น
จำกัดโดเมนอีเมล · ยืนยันอีเมลก่อนเข้าคิว · เพดานคิว 100 รายการ · ขอรหัสซ้ำได้ทุก 3 นาที และไม่เกิน 5 ครั้งต่อวัน
แต่ยังไม่มีการจำกัดตาม IP เพราะ GAS มองไม่เห็น IP ผู้เรียก

## ตรวจก่อนใช้จริง

- [ ] ล็อกอินด้วยรหัสถูก → เข้าได้
- [ ] ล็อกอินด้วยรหัสผิด → ขึ้นข้อความเดียวกับกรณีไม่มีผู้ใช้ (ไม่บอกใบ้)
- [ ] กรอกผิด 5 ครั้ง → ถูกล็อก 15 นาที
- [ ] ยิง `updateItems` โดยไม่มี token ด้วย curl → ต้องถูกปฏิเสธ
- [ ] ส่ง `emp_id` ปลอมใน payload → ชีตต้องบันทึกตัวตนจริง ไม่ใช่ที่ส่งมา
- [ ] `deactivateUser` แล้วรีเฟรชหน้า → ต้องเด้งออก
- [ ] แก้ `expiresAt` ใน localStorage ให้ยาวขึ้นเอง → ต้องยังใช้ไม่ได้ เพราะเซิร์ฟเวอร์ตรวจของจริง
- [ ] ล็อกอินค้างงานไว้แล้ว session หมดอายุ → **งานที่ทำค้างต้องไม่หาย**
- [ ] สมัครด้วยอีเมล gmail.com → ต้องถูกปฏิเสธ
- [ ] สมัครแล้วได้อีเมลรหัส 6 หลักจริง (ทดสอบกับผู้ใช้จริงก่อน อาจเข้าสแปม)
- [ ] ใส่รหัสยืนยันผิด 5 ครั้ง → รหัสถูกยกเลิก ต้องขอใหม่
- [ ] สมัครด้วยรหัสพนักงานที่มีบัญชีอยู่แล้ว → ต้องถูกปฏิเสธ
- [ ] ขอรหัสลืมรหัสผ่านด้วยรหัสพนักงานที่ไม่มีจริง → ต้องตอบข้อความเดียวกับกรณีมีจริง
- [ ] ตั้งรหัสใหม่สำเร็จ → เครื่องอื่นที่ล็อกอินค้างต้องถูกตัดทันที
- [ ] `approveUser` แล้ว → ผู้ใช้ล็อกอินด้วยรหัสที่ตั้งตอนสมัครได้เลย ไม่ต้องเปลี่ยนรหัส

ข้อสุดท้ายสำคัญที่สุดในแง่การใช้งานจริง — คนอาจทำงานมาทั้งวันแล้ว session หมดพอดี
