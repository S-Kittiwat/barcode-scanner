## ลำดับที่ห้ามสลับ

### 1. สำรอง Sheet ก่อน

File → Make a copy เก็บไว้ **ทำก่อนทุกอย่าง**

### 2. เตรียม Script Properties

Apps Script → Project Settings → Script Properties

```
ALLOWED_EMAIL_DOMAIN = brs-group.com        (ใส่หลายโดเมนได้ คั่นด้วย ,)
ADMIN_EMAIL          = <อีเมลผู้ดูแล>
```

**`AUTH_PEPPER` ไม่ต้องสร้างเอง** — รัน `generateAuthPepper()` จากหน้า Apps Script
ระบบจะสร้างและเก็บให้ ปลอดภัยกว่าเพราะไม่ต้องผ่านคลิปบอร์ด
(วิธีสร้างเองจาก Console ดูใน `AUTH.md`)

`AUTH_PEPPER` **ห้ามเปลี่ยนทีหลัง** ถ้าเปลี่ยนทุกคนจะล็อกอินไม่ได้

### 3. แก้ GAS

เขียนให้ตรงกับ `Code.gs` จริงของคุณแล้ว **ไม่ต้องแก้ชื่อฟังก์ชันเอง**

1. วาง `Auth.gs`, `Register.gs`, `Integration.gs` เป็นไฟล์ใหม่ทั้งสามไฟล์
2. ใน `Code.gs` เดิม **ลบเฉพาะ `doGet` กับ `doPost` ทิ้ง** — ฟังก์ชันอื่นเก็บไว้ทั้งหมด
   (`Integration.gs` มี doGet/doPost ตัวใหม่ที่เรียกฟังก์ชันเดิมของคุณครบแล้ว)

`Integration.gs` เรียกฟังก์ชันเดิมเหล่านี้ ต้องยังอยู่ใน `Code.gs`
```
doGetCSV  doGetDashboard  doGetDelivery  doGetBatches  doGetBatchDetail
doGetSiteGroups  doGetIncoming  updateStatus  receiveItems  disputeItems
resolveDispute  splitBatch  submitReport  uploadPhoto  outputJSON
```

**สิ่งที่เปลี่ยนไปจากของเดิม**
- `updateItems` เดิมถูกแทนด้วย `updateItemsIdempotent_` ที่กันข้อมูลซ้ำ
  (ฟังก์ชัน `updateItems` เดิมยังอยู่ ไม่ถูกเรียกแล้ว จะลบหรือเก็บไว้ก็ได้)
- เพิ่ม `uploadPhotos` แบบส่งหลายไฟล์ในคำขอเดียว ของเดิมยังใช้ได้อยู่
- `resolveDispute`, `splitBatch`, `submitReport` รองรับครบ ไม่หายไปไหน

### 4. คอลัมน์ใน Collectionsheet

**ไม่ต้องเพิ่มเอง** — `ensureIdempotencyColumns_()` จะเติมหัวคอลัมน์ `client_id` (S)
และ `updated_at` (T) ให้อัตโนมัติในการบันทึกครั้งแรก

ถ้าอยากเก็บสถิติความแม่นของระบบอ่านอัตโนมัติในอนาคต ค่อยเพิ่ม
`read_source` `system_flag` `human_edited` `sampled` ทีหลังได้

### 5. สร้างชีตของระบบล็อกอิน

รันจากหน้า Apps Script ทีละตัว
```js
setupAuthSheets()
setupRegisterSheets()
```

### 6. ตั้ง trigger รายวัน

Triggers → Add Trigger → Time-driven → Day timer สองตัว
`cleanupExpiredSessions` และ `cleanupExpiredCodes`

### 7. ทดสอบ GAS ก่อนแตะหน้าเว็บ

**ข้อนี้สำคัญที่สุด** ส่ง `updateItems` ด้วย `client_id` เดิมสองครั้ง
→ **ต้องได้แถวเดียว** ครั้งที่สองตอบ `updated`

ถ้าข้อนี้ไม่ผ่าน **หยุด** อย่าไปต่อ เพราะหน้าเว็บใหม่มี retry
ถ้าเซิร์ฟเวอร์ยัง insert อย่างเดียว จะกลายเป็นเครื่องผลิตข้อมูลซ้ำ

### 8. Deploy เป็น New version

จดเลข version ไว้ เผื่อต้องย้อนกลับ

### 9. สร้างบัญชีผู้ดูแลของตัวเองก่อน

เปิด `admin-tool.html` บนเว็บ → กรอกรหัสพนักงานกับรหัสผ่าน → คัดลอกคำสั่งไปรันใน Apps Script

**ห้ามใส่รหัสผ่านดิบใน `addUser()`** จะได้บัญชีที่ล็อกอินไม่ได้
ขั้นตอนละเอียดดูหัวข้อ **สร้างบัญชีผู้ดูแลคนแรก** ใน `AUTH.md`

**ทดสอบล็อกอินให้ผ่านก่อน** แล้วค่อยทำข้อ 10 ถ้าล็อกอินไม่ได้จะกู้ยากมาก

### 10. อัปไฟล์หน้าเว็บทั้งหมด

ตอนนี้ค่อยอัปขึ้น repo

## ทำอย่างไรกับคนที่ใช้อยู่

พอปล่อยเวอร์ชันนี้ **ทุกคนจะถูกเด้งไปหน้าล็อกอินทันที** เพราะ session เดิมไม่มี token

ทางเลือก
- **ให้ทุกคนสมัครเอง** ผ่าน `register.html` แล้วคุณอนุมัติ — เหมาะถ้ามีเวลา
- **สร้างบัญชีให้ล่วงหน้า** ด้วย `addUser()` แล้วแจ้งรหัสชั่วคราวเป็นรายคน — เร็วกว่าถ้ารีบ

**แจ้งทีมล่วงหน้า** และ**อย่าปล่อยในวันใกล้เดดไลน์ MT**

## ถ้าอยากค่อยเป็นค่อยไป

ใน `Code.gs` มีสวิตช์
```js
var REQUIRE_AUTH_ON_GET = true;
```

ตั้งเป็น `false` ก่อนได้ — endpoint แบบ GET จะยังเปิดเหมือนเดิม
ส่วน POST ยังต้องมี token เสมอ ปิดไม่ได้ เพราะเป็นตัวที่เขียนข้อมูล

เปิดเป็น `true` เมื่อมั่นใจว่าทุกหน้าใช้เวอร์ชันใหม่แล้ว

## สิ่งที่เปลี่ยนในหน้าเดิม

การเรียก API ทั้ง 27 จุดถูกเปลี่ยนเป็น `apiPost()` / `apiGetJson()` ซึ่งแนบ token
มี timeout 30 วินาที และ retry อัตโนมัติ

`batch.html` เปลี่ยนเพิ่ม
- ฟังก์ชันซ้ำ 5 ตัวชี้ไปโมดูลร่วม (ตัวอ่าน CSV ใหม่รองรับ comma ในชื่อลูกค้า)
- ทุกแถวมี `client_id`
- อัปโหลดเป็นชุดละ 5 ไฟล์

`delivery.html` / `delivery_batches.html` เดิมเช็ค role อยู่แล้ว ตอนนี้เช็คใน `requireAuth` ด้วย

## `_scan.html`

ไม่มีหน้าไหนลิงก์ถึงเลย และชื่อขึ้นต้นด้วย `_` เหมือนตั้งใจปลดระวาง
ผมแก้ให้เรียบร้อยแล้วเผื่อยังใช้อยู่ **ถ้าแน่ใจว่าไม่มีใครใช้ ลบทิ้งได้**

ถ้าไม่แน่ใจ ปล่อยไว้ก่อนแล้วดู `LoginLog` สักเดือน

## ถ้ามีปัญหา

**ย้อนกลับ** — Deploy → เลือก version ก่อนหน้า และ revert commit ใน repo
ข้อมูลใน Sheet ไม่หาย เพราะเราแค่เพิ่มคอลัมน์

**หาสาเหตุ** — ถามผู้ใช้สามข้อ: เวอร์ชันอะไร (ดูที่ `<html data-docscan-version>`) · หน้าไหน · ทำอะไรอยู่
แล้วดูชีต `ErrorLog` กับ `LoginLog` ตามเวลาที่แจ้ง

**ปัญหาที่เจอบ่อย**
- เปิดหน้าแล้วขาว → ดู Console มักเป็น path ของ `js/` ผิด หรือเปิดผ่าน `file://` (ES module ต้องใช้ https)
- ล็อกอินแล้วเด้งกลับทันที → `AUTH_PEPPER` ไม่ตรงกับตอนสร้างผู้ใช้
- ทุก API ตอบ auth_required → ยังไม่ได้ Deploy version ใหม่
- อีเมลไม่มา → ตรวจสแปม และดูโควตา (บัญชีทั่วไปราว 100 ฉบับ/วัน)

## ยังไม่ได้ทำ

ตามลำดับที่ควรทำต่อ

1. Service Worker + ย้ายไลบรารีเข้า repo → เปิดโปรแกรมได้ตอนเน็ตล่ม
2. ตัวระบายคิว outbox → `js/store.js` เตรียมที่เก็บไว้แล้ว ยังไม่มีตัวส่ง
3. Draft ลง IndexedDB → กันงานหายตอน refresh
4. แก้ `_extractPDFPage()` ที่โหลด PDF ใหม่ทุกหน้า
5. **แล้วค่อยเอา OCR เข้า**
